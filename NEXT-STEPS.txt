Версия 27 заменяет сервер v26. Новый бакет и приватная папка не обязательны: бэкапы шифруются до записи AES-256-GCM; в публичном бакете могут быть доступны зашифрованные объекты и их метаданные, но не открытый JSON. Ключ остаётся только в серверном окружении.
1. Замените в GitHub ВСЕ файлы из архива в корне прежнего репозитория shintop-admin; Dockerfile должен остаться в корне. Никаких .env и ключей в репозиторий.
2. Генератор shintop-backup-key.html откройте локально, создайте и сохраните ключ. Добавьте в Timeweb BACKUP_ENCRYPTION_KEY. Остальные секреты не генерируйте заново.
3. Добавьте BACKUP_PREFIX=encrypted-catalog-backups.
4. ADMIN_ORIGIN должен быть точным HTTPS-адресом ПАНЕЛИ (не сайта магазина). Если он пока неизвестен, не угадывайте: нужен следующий экран настройки домена Timeweb.
5. Пока не запускайте платное приложение до проверки всех переменных.
Проверки шифрования выполнены локально. Реальный S3, IfMatch и CDN требуют отдельной проверки после настройки: если условная запись не поддерживается, сервис откажет в публикации. Проверять сперва на копии каталога с отдельным CATALOG_KEY.
Один worker/одна реплика обязательны для встроенного ограничения попыток. restore_backup.py расшифровывает скачанную копию локально, не публикует её. При потере ключа восстановление невозможно. Сохраните ключ отдельно в менеджере паролей; не меняйте его без сохранения старого для прежних копий.
Это подготовленные файлы, не работающая на вашем сайте публикация.
